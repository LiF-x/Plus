# Security Policy

## Reporting a vulnerability

If you discover a security issue in Pluss, please report it privately rather
than opening a public issue, so it can be addressed before details are widely
known.

The preferred way to report is through GitHub's private vulnerability reporting:

1. Go to the **Security** tab of the repository.
2. Click **Report a vulnerability**.
3. Fill in as much detail as you can (see below).

If private reporting is not available to you, you may instead contact the
maintainer directly through their GitHub profile: https://github.com/LiF-x

### What to include

A good report helps a lot. Where possible, please provide:

- A clear description of the issue and its impact.
- Step-by-step instructions to reproduce it.
- The affected version, commit, or target binary.
- Any proof-of-concept, logs, or screenshots.
- Suggested remediation, if you have one.

### What to expect

- Acknowledgement of your report as soon as the maintainer is able to review it.
- An assessment of the issue and, if confirmed, a plan and timeline for a fix.
- Credit for the discovery once a fix is released, if you'd like to be named.

## Scope and responsible use

Pluss involves binary analysis and patching. Please only test against software
and systems you own or are explicitly authorised to modify. Reports that
require illegal access to third-party systems cannot be accepted.

## Supported versions

Security fixes are applied to the latest released version on the default
branch. Older versions are not maintained unless stated otherwise.
